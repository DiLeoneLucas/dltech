GLT

Goal Line Technology — Análise Geométrica de Contato entre Bola e Linha

Versão: Android
Plataforma: Android
Projeto: GLT
Desenvolvimento: Lucas Fernandes Di Leone

1. Sobre o projeto

O GLT (Goal Line Technology) é um aplicativo Android desenvolvido para auxiliar na análise visual e geométrica de situações de contato entre uma bola e uma linha de referência.

O aplicativo utiliza a câmera do dispositivo para exibir a situação analisada e permite que o usuário posicione manualmente elementos geométricos sobre a imagem, ajustando dimensões, ângulos e posições para realizar a verificação.

A proposta é oferecer uma ferramenta de análise visual com controle manual, simplicidade de utilização e flexibilidade para diferentes perspectivas de câmera.

2. Objetivos

  • Facilitar a análise de contato entre bola e linha.
  • Permitir ajustes geométricos manuais.
  • Simular visualmente recursos de análise inspirados no VAR.
  • Oferecer uma interface simples e intuitiva.
  • Permitir a utilização da câmera do smartphone durante toda a análise.

3. Funcionalidades

3.1. Câmera

  • Utilização da câmera do dispositivo Android.
  • Priorização da melhor qualidade de câmera disponível.
  • Controle para ativar e desativar o flash.
  • Visualização da imagem durante os ajustes.

3.2. Marcação geométrica

  • Seleção manual da linha de referência.
  • Marcação manual dos dois elementos utilizados na análise.
  • Posicionamento independente dos elementos na imagem.
  • Movimentação livre dos elementos.

3.3. Ajustes de diâmetro e formato

  • Inserção manual do diâmetro em milímetros.
  • Ajuste de diâmetro por controle circular (dial).
  • Possibilidade de utilizar formato oval.
  • Ajuste do ângulo de inclinação.
  • Adaptação geométrica para diferentes perspectivas da câmera.

3.4. Travamento geométrico

O recurso Travar Diâmetro permite bloquear as configurações geométricas dos elementos.

Com o travamento ativado:

  • O diâmetro não pode ser alterado.
  • O ângulo não pode ser alterado.
  • O formato não pode ser editado.
  • A movimentação dos elementos continua permitida.

3.5. Interface

  • Tela inicial com identidade visual própria.
  • Mensagem de abertura: "Chama o VAR".
  • Painel de configurações deslizante na parte inferior.
  • Área de configurações com rolagem.
  • Preservação da visualização da câmera durante os ajustes.
  • Botão de ação: "Verificar Falta".

4. Filosofia do projeto

O GLT utiliza uma abordagem de análise manual assistida.

O reconhecimento automático por inteligência artificial foi retirado da proposta devido às inconsistências encontradas na identificação da bola e da linha.

A prioridade do desenvolvimento é garantir:

  • Precisão nos ajustes manuais.
  • Controle geométrico dos elementos.
  • Estabilidade da interface.
  • Facilidade de utilização.
  • Previsibilidade no comportamento dos controles.

Diretriz de desenvolvimento: o reconhecimento automático por IA não deve ser reintroduzido. O foco do GLT permanece nos ajustes geométricos realizados manualmente pelo usuário.

7. Compilação do aplicativo

O projeto utiliza o GitHub Actions para automatizar a geração do APK, dispensando a necessidade de instalar o Android Studio na máquina utilizada para o desenvolvimento.

7.1. Configuração do ambiente

Componente Versão
Java 17
Gradle 8.9
Android SDK 35
Build Tools 35.0.0

7.2. Processo de compilação

  • Acesse o repositório no GitHub.
  • Entre na aba Actions.
  • Selecione o workflow Android.
  • Execute a compilação ou aguarde a execução automática após o envio das alterações.
  • Aguarde a conclusão do processo.
  • Acesse os artefatos gerados pelo workflow.
  • Baixe o APK para instalação no dispositivo Android.

8. Versionamento

O projeto utiliza versionamento sequencial para identificar as entregas compactadas.

Exemplo de nomenclatura:

GLT-V6.zip
GLT-V7.zip
GLT-V8.zip
GLT-V9.zip
GLT-V10.zip
GLT-V11.zip

Cada nova entrega deve incrementar a numeração, mantendo o histórico organizado e evitando a substituição indevida de versões anteriores.

9. Diretrizes de desenvolvimento

As próximas atualizações devem respeitar os seguintes princípios:

  • Preservar funcionalidades já implementadas e validadas.
  • Não reintroduzir o reconhecimento automático por IA.
  • Manter a movimentação dos elementos mesmo com o travamento geométrico ativado.
  • Preservar a visualização da câmera durante os ajustes.
  • Validar o funcionamento de todos os botões e menus.
  • Revisar os arquivos antes de cada nova entrega.
  • Evitar arquivos desnecessários ou suspeitos no pacote.
  • Documentar alterações relevantes no código.
  • Manter a compatibilidade com o ambiente de compilação configurado.

10. Roadmap

A evolução do GLT contempla as seguintes etapas:

Etapa 1 — Estrutura inicial

  • Desenvolvimento da estrutura inicial do aplicativo.
  • Implementação da identidade visual GLT.
  • Configuração da câmera.

Etapa 2 — Controles geométricos

  • Controles geométricos manuais.
  • Ajustes de diâmetro.
  • Suporte a formatos ovais.
  • Ajuste de inclinação.
  • Conceito de travamento geométrico.

Etapa 3 — Compilação e estabilidade

  • Configuração de compilação via GitHub Actions.
  • Consolidar uma versão estável de referência.
  • Validar o comportamento geométrico em diferentes perspectivas.
  • Realizar testes completos em dispositivos Android.

Etapa 4 — Evolução

  • Aprimorar a apresentação dos resultados da verificação.

11. Observações

O GLT é um projeto experimental de análise geométrica e visual. Não deve ser considerado um equipamento oficial de arbitragem nem substitui os sistemas certificados de Goal-Line Technology utilizados em competições profissionais.

Os resultados dependem do posicionamento da câmera, da qualidade da imagem e da precisão dos ajustes realizados pelo usuário.
